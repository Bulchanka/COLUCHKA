# Колючка

`Колючка` — demo-продукт для подготовки пациента с сезонным аллергическим ринитом к повторному приёму врача.

Пациент фиксирует самочувствие между визитами, добавляет контекст (лечение, фото, окружение и голосовые заметки), а врач получает единую хронологию и компактную сводку. Patient web и doctor web работают с одной доменной моделью `MedicalRecord`.

> **Важно:** проект предназначен для demo и проверки продуктовой гипотезы. Он не ставит диагноз, не заменяет врача и не подключён к настоящей ЕМИАС.

## Статус проекта

Текущая версия — локальный MVP для сценария «между приёмами».

- **Условный продуктовый вывод исследования:** продолжать узкий пилот подготовки к повторному приёму.
- **Не является доказанным свойством продукта:** уникальность платформы, экономия, выбор анализов или прогнозирование приступов.
- Данные пациентов синтетические.
- Хранилище — in-memory; после перезапуска dev-сервера данные сбрасываются.
- Внешние провайдеры имеют demo/fallback-режимы.

Исследовательский документ `research_sbermed_ai.md` используется как контекст и набор проверяемых гипотез, а не как инструкция по эксплуатации приложения.

## Возможности demo

### Сценарий пациента

- вход через Mock EMIAS;
- ежедневный check-in с оценкой самочувствия и симптомами;
- подтверждение черновика перед сохранением медицински значимой записи;
- помощник для записи наблюдений между визитами;
- история записей и календарь;
- профиль, назначения и контекст заболевания;
- голосовой ввод с обязательным просмотром транскрипции;
- фото и отчёт перед визитом;
- окружение: погода, качество воздуха и пыльца в demo-режиме.

### Сценарий врача

- список доступных синтетических пациентов;
- история пациента;
- AI-сводка к повторному приёму;
- просмотр лечения, графика симптомов и происхождения данных;
- экспорт отчёта в PDF.

## Быстрый старт

Требования: Node.js с npm.

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000/login](http://localhost:3000/login).

Для Windows также можно запустить `start.bat` двойным кликом: скрипт установит зависимости при необходимости, запустит сервер и откроет экран входа.

### Demo-аккаунты

Вход выполняется через Mock EMIAS. В проекте есть 100 синтетических пациентов и 5 врачей. Общий demo-пароль:

```text
test58
```

Основные аккаунты:

- **Анна Петрова** — patient flow;
- **Елена Смирнова** — doctor flow.

Полный список аккаунтов находится в [`ACCOUNTS_DEMO.md`](./ACCOUNTS_DEMO.md).

## Сквозной сценарий демонстрации

1. Войдите как Анна Петрова.
2. Откройте `/patient/check-in`, заполните форму и подтвердите черновик.
3. Проверьте новую запись на `/patient/history`.
4. Откройте `/patient/assistant`, отправьте наблюдение и подтвердите подготовленную запись.
5. Выйдите из аккаунта.
6. Войдите как Елена Смирнова.
7. Откройте `/doctor/patients/anna` и покажите историю, AI-сводку, лечение и график.
8. При необходимости проверьте режимы провайдеров на `/demo-status`.

Подробный runbook: [`DEMO_RUNBOOK.md`](./DEMO_RUNBOOK.md).

## Конфигурация

Скопируйте `.env.example` в `.env.local` и задайте нужные значения:

```env
OPENAI_BASE_URL=https://example.com/v1
OPENAI_API_KEY=REPLACE_WITH_YOUR_KEY
OPENAI_MODEL=
OPENAI_MODE=live

YANDEX_MAPS_API_KEY=
NEXT_PUBLIC_YANDEX_MAPS_API_KEY=
YANDEX_WEATHER_API_KEY=
YANDEX_STT_API_KEY=
YANDEX_FOLDER_ID=
YANDEX_STT_LANG=ru-RU
YANDEX_STT_SAMPLE_RATE_HZ=

ENVIRONMENT_MODE=demo
MOCK_EMIAS=true
```

Без настроенных внешних ключей приложение использует demo/fallback-данные. AI вызывается только server-side через единый OpenAI-compatible слой.

Голосовая кнопка записывает Ogg Opus в браузере и отправляет его на Yandex SpeechKit. Для live-режима нужны `YANDEX_STT_API_KEY` и `YANDEX_FOLDER_ID`. Если браузер не поддерживает запись Ogg Opus, используется встроенное браузерное распознавание.

## Архитектура

Приложение — монолитный Next.js MVP без микросервисов. Это упрощает проверку сквозного сценария и позволяет patient и doctor flow использовать одну запись.

```text
app/                 страницы и API routes Next.js
components/          UI-компоненты
lib/domain.ts        доменные типы, synthetic BDE и адаптер медсистемы
lib/store.ts         единый in-memory MedicalRecord
lib/assistant.ts      структурирование сообщений и AI-проверка
lib/symptom-normalizer.ts
                     нормализация бытовых описаний симптомов
data/                словари и demo-данные
public/               статические ресурсы
```

Для production предполагается заменить `lib/store.ts` на repository с постоянным хранилищем, а `MockMedicalSystemAdapter` — на адаптер реальной медицинской системы без изменения основного patient workflow.

## API

Основные endpoints:

| Метод | Endpoint | Назначение |
|---|---|---|
| `POST` | `/api/session` | demo-вход по `accountId` |
| `GET` | `/api/session` | текущая сессия и профиль |
| `DELETE` | `/api/session` | выход |
| `GET` | `/api/record` | медицинская запись пациента |
| `POST` | `/api/checkins` | сохранение подтверждённого check-in |
| `POST` | `/api/assistant` | сообщение помощнику и подготовка записи |
| `GET` | `/api/doctor/patients` | список пациентов врача |
| `GET` | `/api/doctor/patients/:id` | сводка пациента |
| `POST` | `/api/reset` | сброс demo-данных для врача |

Проверка словаря нормализации доступна через `POST /api/symptom-normalize`, например:

```json
{
  "text": "После еды меня обсыпало, губы раздуло"
}
```

Нормализатор переводит бытовые фразы в стандартизированные признаки и красные флаги, но не ставит диагноз.

## Правила безопасности demo

- Запись сначала создаётся как черновик и сохраняется только после явного подтверждения пользователя.
- AI структурирует введённые сведения, но не должен добавлять неупомянутые факты.
- Отрицания сохраняются: «кашля нет» не превращается в «кашель».
- Помощник не ставит диагноз, не назначает и не отменяет лечение.
- Голосовая транскрипция показывается пользователю до отправки и подтверждения.
- При недоступности внешнего провайдера показывается demo/fallback-режим и происхождение данных.
- Настоящие медицинские данные и настоящая ЕМИАС не используются.

Полные правила: [`SAFETY_RULES.md`](./SAFETY_RULES.md).
